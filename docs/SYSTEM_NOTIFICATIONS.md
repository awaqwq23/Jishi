# 系统通知修复与验收

用户要求手机应用外通知栏提醒、电脑到时右下角提醒。应用内弹窗不能替代系统通知。

## 本次修复

- 鸿蒙 0.3.6（3000006）：通知改用 SERVICE_INFORMATION；原 CONTENT_INFORMATION 的默认等级不显示状态栏图标、横幅或声音。即时通知和代理提醒使用一致类别与通知标识。保留未变更的代理提醒，避免刷新任务列表取消正在到时的提醒。关闭提醒或退出账号才明确清空。
- Windows 0.4.10：保留原生通知对象并等待系统接受；系统通知接口失败时打开独立桌面提醒窗口。到时记录只有发送被接受后才移除，失败可重试、重启仍保留。同一提醒在网页与后台触发时去重。
- 网页前台到时检测始终尝试系统通知，不再因存在定时接口就跳过。手机发送结果由原生回执确认；新旧客户端增量兼容。测试按钮不再用页面弹窗冒充系统通知。
- Android 0.4.10 候选：检查应用及提醒通知渠道权限、反馈发送结果并去重。缺少原发布密钥，目前只有未签名候选；正式 Android 仍保留 0.4.7，不能将候选当作可升级正式包。

## 已验证与实际限制

通知发送成功表示系统接口接受请求，不能保证用户没有开启勿扰模式、关闭横幅或静音。系统设置仍控制最终展示。

自动回归覆盖原生发送确认、失败重试、重启、去重、鸿蒙通知类别、权限拒绝和到时清队列竞态。Windows 安装后的真实 Electron 程序已由构建任务执行定时通知冒烟，结果见发布记录。鸿蒙已官方 SDK 编译、正式签名和验签，但尚无连接的鸿蒙真机，不能声称通知栏、锁屏及应用关闭后的实测已通过。

鸿蒙委托系统保存未来 21 天最近 30 个提醒；打开应用和内容变更时补充。Windows 开启提醒后设置随系统登录后台启动，关闭主窗口保留托盘运行；主动选择托盘“退出”或关闭电脑后不能弹出，到再次启动会补发最近一天的到时提醒。Android 普通关闭应用保留系统闹钟，系统强制停止会阻止闹钟。

## 真机验收

1. 安装对应最新版，在“设置”开启本设备提醒并允许系统通知。点击“发送测试提醒”，确认手机通知栏或电脑桌面出现“拾光记事测试提醒”。
2. 新建两分钟后到期的待办，保持应用打开，检查应用外通知。完成或删除后不应再收到未来提醒。
3. 再新建两分钟后到期待办：鸿蒙返回桌面并从最近任务关闭应用，Windows 关闭主窗口保留托盘；到时检查系统通知。
4. 临时关闭系统通知权限，测试按钮应反馈失败，不应显示虚假的“已成功连接”。恢复权限后重新开启并测试。
5. 离线保存定时待办，保持本机正常运行，检查到时通知；重新联网后不得因为同步再次发送同一个提醒。

生产发布尚需项目 AGENTS.md 规定的最终明确确认，商店上传需要有效 AGC 登录。APP 备案仍由用户办理。
