# 记时定期任务合并与多端通知修复记录

## 用户要求

- 合并“定期任务”和“习惯”，新版界面只保留“定期任务”，删除重复入口和无意义的模板内容。
- 修复电脑、手机和网页在开启提醒后仍不弹窗、不发系统通知的问题。
- 完善 Web 和 HarmonyOS 版本；为 Web 增加 `jishi.awaqwq233.com` 子域名，同时保留 `https://awaqwq233.com/note/` 和旧客户端兼容行为。
- 打开华为开发者注册页面；用户完成注册、实名和验证码后继续签名、构建与发布 HarmonyOS 应用。

## 实现内容

### 定期任务与习惯

- Web 侧删除独立“习惯”导航、列表、编辑器和导入导出入口，所有既有 `routine`、`habit` 数据统一展示在“定期任务”中。
- 新建项目继续使用兼容值 `routine`；编辑旧 `habit` 数据时保留原始类型，避免旧客户端读取失败。
- 定期任务新增“定时提醒”开关；关闭后按全天计划展示，兼容原习惯无时间的用法。
- 新增统一的 `schedules` 导入导出分区。旧 `routines`、`habits` API、字段和返回行为继续保留，供 Windows/Android 0.4.x 与旧 PWA 使用。

### 通知修复

- Web：到点时始终显示应用内提醒弹窗；浏览器允许时再发送 Service Worker/Notification 系统通知。即使浏览器不支持系统通知，也可开启和测试页面内提醒。
- Web：设置页增加提醒状态、开关、测试按钮和权限排查提示。
- Windows 0.4.5：使用隔离 preload 桥把未来 21 天、最多 300 条提醒同步到 Electron 主进程；关闭窗口后驻留托盘，继续计时并发送 Windows 系统通知，托盘菜单可明确退出。
- Android 0.4.6（`versionCode 11`）：使用 AlarmManager 保存未来 21 天、最多 300 条提醒；支持 Doze、进程退出、开机和应用升级后恢复；Android 13+ 正确请求通知权限；没有精确定时特殊权限时自动降级为系统允许的后台非精确定时。
- 通知键值在 Web 与原生调度器间保持稳定，重同步会取消旧闹钟，避免重复累积。

### Web 与 HarmonyOS

- Web 移动端底部导航从五项精简为四项，新增自适应提醒弹窗样式和合并后的定期任务编辑体验。
- HarmonyOS 升级为 0.3.0（`versionCode 3000000`），主站设为 `https://jishi.awaqwq233.com/`，失败时自动切换 `https://awaqwq233.com/note/`，并提供重试/切换错误页。
- HarmonyOS 增加 `JishiHarmony/0.3.0` User-Agent、受限的 `JishiNative` 通知桥、系统通知授权和即时通知；未向 Web 暴露认证凭据。
- 移除不适用于普通三方应用的 `ohos.permission.NOTIFICATION_CONTROLLER`。AppGallery 后台代理提醒能力需在开发者账号与应用创建完成后申请，随后再实现进程退出后的 HarmonyOS 系统定时提醒。

## 兼容与安全

- 未删除或改名旧 API 路径、Cookie、请求/响应字段、`/note` 基路径或备用站行为。
- Server 仅放宽定期任务时间为可空，并增量加入 `schedules` 数据分区；数据库没有修改历史迁移，也没有新增迁移。
- `routines`、`habits` 导入导出继续按原类型工作；新 `schedules` 分区可同时携带两种旧数据。
- 生产秘密、数据库、媒体、Nginx 生产配置和更新清单尚未改动。
