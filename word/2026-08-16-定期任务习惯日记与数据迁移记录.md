## 完成的修复与功能

### 1. 自定义提醒时间单位

- 每一个提前提醒时间都改为“数值 + 单位”的独立输入。
- 单位可选择小时、分钟或秒，每个提醒组最多 8 个时间点。
- 原有提醒数据仍按分钟兼容保存；秒会转换为分钟小数，旧数据无需迁移。
- 通知检查频率提高到 1 秒，使按秒设置的提醒能够正常触发。

### 2. 卡片透明度

- 修正卡片背景颜色写法，让透明度变量真正作用于待办、定期任务和日记卡片。
- 降低自定义背景上方原本过厚的页面遮罩，避免卡片与页面底色接近而看不出透明变化。
- 设置页新增带纹理的即时预览，拖动时直接展示效果，松开、键盘调整结束或失焦时才保存一次。
- 服务端统一把透明度限制在 15% 至 100%，避免非法数值造成界面异常。

### 3. 定期任务

- 新增独立的“定期任务”模块和数据库表。
- 支持单次、每天、每周、选定周几、节假日/周末等重复方式，并支持开始日期、计划说明和精确到秒的执行时间。
- 按选中日期分别显示未完成、已完成和回收站内容。
- 左滑标记完成或重新打开，右滑移入回收站；回收站支持恢复和永久删除。
- 页面运行且本设备提醒已开启时，会在定期任务设定时间发送通知。

### 4. 习惯

- 新增独立的“习惯”模块，共用可靠的周期计划与完成记录模型，但不要求具体时间。
- 支持单次、每天、每周、选定周几、节假日/周末等规则。
- 按日期分别显示未做到、已做到和回收站内容。
- 左滑记录做到或改为未做到，右滑移入回收站；回收站支持恢复和永久删除。

### 5. 日记

- 新增独立的“日记”模块，每个账号每天保存一篇日记。
- 默认打开当天，可通过日期或历史列表查看和修改以前的日记。
- 停止输入 0.8 秒后自动保存到服务器；切换日期时会刷新尚未发送的最后内容。
- 自动保存加入修订号与请求竞态保护，避免较早的保存结果覆盖继续输入的新内容。

### 6. 分模块导入与导出

- 设置页新增“数据导入与导出”，可分别处理账户配置、待办、定期任务、习惯和日记。
- 每个模块可导出 JSON 备份，也可导出便于阅读和归档的 Markdown 文档。
- JSON 文件包含格式版本、模块标识和导出时间；导入时校验格式与模块是否匹配。
- 导入只替换当前账号对应模块的数据，不会影响其他账号；操作前会再次确认。
- 账户配置备份包含昵称、界面设置、分类和提醒组，不包含密码、登录凭据或会话。
- 待办导入按分类名和提醒组名重新关联，定期任务与习惯导入会重新建立完成记录关系。

## 数据库与接口

- 新增 `schedule_items`：定期任务和习惯计划。
- 新增 `schedule_records`：按日期保存完成/做到记录。
- 新增 `diary_entries`：按日期保存日记。
- 新增计划增删改、完成记录、日记自动保存、分模块 JSON/Markdown 导出及 JSON 导入接口。
- 新增增量数据库迁移 `0001_modules_and_portability.sql`，不会删除现有待办和账户数据。

## 规则说明

- 当前“节假日/周末”按周六、周日执行。中国法定节假日及调休需要独立年度日历数据，界面中已明确显示当前规则，避免把周末规则误认为官方调休日历。
- JSON 导入属于“替换对应模块”，建议导入前先导出该模块的 JSON 备份。

## 登录故障与恢复

- 部署后 Windows 0.4.4 客户端重新登录时显示“操作没有完成，请稍后重试”。
- Nginx 访问日志显示 `/api/auth/login` 连续返回 HTTP 500；`jishi-api` 原始堆栈显示缺少符合要求的 `AUTH_SECRET`。
- 根因是部署同步使用 `rsync --delete` 时，没有排除被 Git 忽略的生产专用 `/opt/jishi/server/.dev.vars`，导致该文件被删除。
- 已得到用户确认后，从部署前备份中只恢复 `.dev.vars`，所有者恢复为服务账号、权限恢复为 600，并重启 `jishi-api`。
- 恢复后 API 健康检查正常；服务器内部无效账号登录正确返回 JSON 401，公网登录代理链也返回 HTTP 401 和 `application/json`，不再返回 500。
