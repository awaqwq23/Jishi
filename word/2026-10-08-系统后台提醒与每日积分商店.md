# 2026-10-08 系统后台提醒与每日积分商店

## 用户要求

- Windows 不打开应用窗口也能在系统通知区域提醒。
- 安卓和鸿蒙在手机通知栏提醒，不只在应用内显示。
- 每日签到，分别自定义签到、任务、习惯完成奖励和未完成扣分。
- 自定义奖励商品和所需积分，余额足够才扣分兑换，实际奖励自行兑现。
- 用户明确允许忽略缺失的发布守护技能并要求删除。指定路径及当前用户对应路径均不存在，没有实体文件可删除；已移除 AGENTS.md 对该缺失技能的强制引用。其余兼容、秘密保护、测试和生产最终确认规则保留。

## 实现

- Windows 使用持久提醒队列，保存未来 366 天内最近 300 条提醒；开启提醒设置系统登录后后台启动，不显示主窗口。关闭窗口驻留托盘。恢复队列不依赖服务器在线；长延迟不使用会溢出的单次定时器，重启和恢复后避免重复投递。完全退出进程后本次登录暂停，重新启动或下次系统登录恢复。
- 安卓继续使用系统 AlarmManager、通知栏和重启恢复；补充应用通知总开关检测、权限设置页引导、调度异常反馈和通知栏单色图标。
- 鸿蒙继续使用既有系统代理提醒；Web 避免重复发送已由原生调度的通知，并说明必须安装具备代理提醒授权的签名版本。远端最新记录确认测试 HAP 的 Profile 尚无代理提醒授权，不能声称已解决真机后台提醒。
- 增加“打卡 · 商店”导航，手机导航增加“积分”。积分与商品按账号保存，积分记录可查看。
- 按北京时间结算。用户保存规则后开启计分，开启前不追溯奖惩。待办有截止时间才扣逾期分；签到和定期任务/习惯于次日结算，离线期间下次同步补算。取消完成撤回奖励；补完成退回该次扣分；再次完成不重复奖励。余额允许为负数。
- 商品支持新增、编辑、删除。兑换用单条 SQL 现场检查余额并扣分；兑换标识在本机按账号保存，网络失败和刷新后可以确认原请求，防止重复扣款。
- 新增编号迁移 `0003_points_and_shop.sql`，旧 API 路径、字段与登录 Cookie 保留，bootstrap 和完成接口只增量返回 points 字段。
- 原生版本候选：Windows 0.4.7、Android 0.4.8 / versionCode 13。Electron 升级到 43.7.9；Capacitor Android/Core 升级到 7.6.9，独立及 workspace 锁文件同步。
